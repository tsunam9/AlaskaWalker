# Numinar mock backend

A Flask reimplementation of the canvasser-facing Numinar origins used by the
stock Android app:

- `auth.numinar.com` (Auth0 passwordless and refresh flows)
- `fast-api.numinar.com/api` (profile, org, project, voter, interaction, push,
  contact, payment, and leaderboard surfaces)
- `rust-server.numinar.com` (ROS/Twilio/Bandwidth seed responses and SSE)

The recovered contracts in `../../numinar/audit/` are ground truth. Comments
marked **[H]** identify response details the client does not reveal and which
must be checked during the repointed-stock-app run.

## Run

```bash
python3 numinar_mock.py
```

The default listener is `0.0.0.0:19002`. Environment variables:
`PM_HOST`, `PM_PORT`, `PM_STATE_PATH`, `PM_CAPTURE`, `PM_CAPTURE_DIR`,
`PM_DASH_USER`, `PM_DASH_PASS`, `PM_ACCESS_TTL_S`, `PM_REFRESH_TTL_S`, and
`PM_OTP_TTL_S`. Web Auth ID tokens are signed by a persistent, gitignored
mock-only RSA key (`mock-signing-key.pem`, override with `PM_OIDC_KEY_PATH`),
and the public key is served from `/.well-known/jwks.json` for the stock
Auth0.Android verifier.

Fixture accounts are `canvasser@example.test` and the email-verification test
account `unverified@example.test`. Passwordless codes are printed to stdout and
shown on the Basic-authenticated dashboard at `http://127.0.0.1:19002/__mock/`
(default credentials `admin` / `testpass123`).

State needed across restarts is atomically persisted to the gitignored
`runtime-state.json`. The default 240-voter fixture is deterministic, grouped
into two-person Anchorage households, and generated by
`fixtures/generate_voters.py`.

The voter download encoding matches the shipped Android `GzipModule` exactly:
column-oriented JSON encoded as UTF-8, RFC 1952 gzip-compressed, then standard
Base64 without line wrapping.

## Tests

Start a fresh mock and run the gates in order:

```bash
PM_PORT=8898 PM_STATE_PATH=/tmp/numinar-test-state.json PM_CAPTURE=0 python3 numinar_mock.py
scripts/test_auth0.sh http://127.0.0.1:8898
scripts/test_core.sh http://127.0.0.1:8898
scripts/test_interactions.sh http://127.0.0.1:8898
scripts/simulate_workflow.py http://127.0.0.1:8898
```

The server also accepts the stock `/websocket` upgrade so the client's
`websocketUp`-gated offline drain can proceed.
